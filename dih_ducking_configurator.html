      DIH Routing Architecture — KEY, DUCK and External SIDECHAIN

      They are distinct features—not interchangeable switches. Some DIH engines intentionally link KEY to a detector; others allow DUCK and KEY to work independently. The audible output, key/reference input, and parameter target must be documented for the individual plugin, not inherited from a universal ducking template.

      KEYPlugin-specific interpretation, detector selection, or processing enable. Its exact meaning differs by engine.
      DUCKPlugin-specific gain-reduction amount/target. It may affect broadband audio, a spectral region, an added layer, or wet effects.
      External SIDECHAINSeparate host-provided signal, when available. It must not automatically become audible output.

      Examples: LookOut has independent KEY and DUCK paths; SacredVerb ducks a wet effects layer; NTRPL 1.0.9 still requires a layer-only bounce before detector behavior is claimed. This page does not claim their engines share the same signal law. An enabled UI control is not proof a host key is connected.

      Routing Templates

      Logic Pro routing tips

      Keep the source audible. Create a separate detector send; its auxiliary may be No Output ONLY if Logic still supplies the external key. For wet reverb/delay ducking, create another send to an audible 100%-wet effects return, insert the ducking processor after the effect, and route the return to the mix. Never set an audible return to No Output. Confirm each path by listening and metering.

      Track / bus / return best practices

      Label key buses (Kick Key, Vocal Key, Narration Key). Effect returns are wet-only. Never route a return into its own key. Every audible group and return feeds the mix once.
